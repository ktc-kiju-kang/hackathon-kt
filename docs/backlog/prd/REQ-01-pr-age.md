# REQ-01 열린 PR의 경과 시간과 마지막 업데이트 시각

> 인덱스: [prd.md](../prd.md) — 상태·Issue는 인덱스 표에서 관리한다. 이 파일은 REQ-01의 근거와 확인 조건(AC)의 원본이다.

## 근거 원문
- SRC-01: "현황판에서 열린 PR마다 열린 지 얼마나 됐는지와 마지막 업데이트 시각을 볼 수 있어야 한다."

## 설명
- 관련 흐름: FLOW-01 ([experience.md](../experience.md))

누가: 현황판(`/dashboard`)을 보는 팀원. 무엇을: GitHub 칸의 "열린 PR" 목록에서 PR마다 열린 지 얼마나 됐는지(경과 시간)와 마지막 업데이트 시각을 본다. 왜: 오래 멈춘 PR을 한눈에 찾아 반나절 안에 머지하기 위해 (`CLAUDE.md` "오래 열린 브랜치" 규칙).

현재 상태 (읽기만 해서 확인, 구현 방법은 정하지 않음): `docs/contracts/dashboard.md`의 `GET /api/dashboard/github` 응답 `pulls`에는 PR이 열린 시각·업데이트 시각이 없고, 화면의 열린 PR 줄은 작성자·브랜치·초안 여부·CI 상태만 보인다. 그래서 이 REQ에는 API AC와 화면 AC가 모두 있다.

범위 안: 목록에 보이는 열린 PR 전부(초안 포함, Q4). 범위 밖: 열린 PR 개수 상한(현재 10개) 변경(Q5), 24시간 넘은 PR 강조(REQ-02).

## 확인 조건 (AC)

| AC | 조건 | 종류 | 확인 | 시험 |
|---|---|---|---|---|
| AC-01-1 | 현황판의 GitHub 현황 응답에 열린 PR마다 PR이 열린 시각과 마지막 업데이트 시각이 들어 있고, 그 값이 GitHub에 기록된 그 PR의 값과 같다 (Q3, Q4) | 정상 | API | TC-01-1 |
| AC-01-2 | 현황판 "열린 PR" 목록의 PR 줄마다 열린 지 얼마나 됐는지가 현재 시각 기준으로 보인다 — 1시간 미만은 "n분", 24시간 미만은 "n시간", 그 이상은 "n일 n시간" (Q1) | 정상 | 화면 | TC-01-2 |
| AC-01-3 | 현황판 "열린 PR" 목록의 PR 줄마다 마지막 업데이트 시각이 한국 시간 "MM-DD HH:mm" 형식으로 보인다 (Q2) | 정상 | 화면 | TC-01-3 |
| AC-01-4 | GitHub 현황을 불러오지 못하면 열린 PR 칸에 경과·업데이트 시각 대신 오류 안내가 보이고, 현황판의 다른 칸은 그대로 보인다 | 오류 | 화면 | TC-01-4 |

## 가정·질문
- Q1 경과 시간 표기 단위·기준 시각 — 가정 (AC-01-2)
- Q2 업데이트 시각 형식 — 가정 (AC-01-3)
- Q3 "마지막 업데이트"의 뜻 — GitHub이 기록한 PR 업데이트 시각 그대로, 가정 (AC-01-1)
- Q4 초안 PR 포함 — 가정 (AC-01-1)
- Q5 열린 PR 개수 상한(현재 10개)은 그대로 둔다 — 가정, AC 없음
